# 面试模拟器 · 修改与重新打包指南

> 本文面向后续需要调整功能/界面的你。所有修改都在项目目录 `~/interview-simulator` 内完成。

---

## 0. 三条黄金流程

```bash
cd ~/interview-simulator

# ① 每次改完代码先做类型检查（能拦住大部分低级错误）
npm run typecheck

# ② 开发模式预览（改界面/逻辑后实时看效果，窗口自动热更新）
npm run dev

# ③ 确认没问题后重新打包成安装包（产出在 dist/）
npm run build:mac
```

> `npm run dev` 和 `npm run build:mac` 都会执行构建；改完代码直接跑 ③ 也行，但建议先 ①②。

## 2. 常见修改场景 → 改哪里

| 想改什么 | 去哪个文件 | 说明 |
|---|---|---|
| 各环节题目数量 / 自我介绍时长 | 设置页里直接改，无需改代码 | 存于 `settings.json` |
| 面试官 4 种预设风格的描述 | `src/main/interview.ts` 的 `PRESET_DESC` | 直接改中文描述即可 |
| 追问深度/英语难度/压力 1-5 档描述 | `src/main/interview.ts` 的 `levelLabel` 调用处 | 每档对应一句描述 |
| 每个环节的面试官规则（出题/点评/提示规则） | `src/main/interview.ts` 的 `stageRules()` | 最核心，改提示词 |
| 面试官语气/行为补充要求 | 面试页「自由描述」框，或 `PRESET_DESC` | 优先用界面自由描述 |
| 评分维度 / 评语要求 | `src/main/report.ts` 的 `SCORE_PROMPT` | 改维度名、分数范围 |
| TTS 音色列表 | `src/renderer/src/pages/Settings.tsx` 的 `ZH_VOICES`/`EN_VOICES` | 改/加音色 ID |
| 界面文字/按钮/布局 | 对应 `pages/*.tsx` + `styles/global.css` | React 组件，改 JSX |
| 新增一个设置项 | `src/shared/types.ts`（加字段）→ `store.ts`（默认值）→ `Settings.tsx`（界面）→ 需要处读取 | 三步走 |
| 录音间隔 / 识别策略 | `src/renderer/src/pages/Interview.tsx` 的录音部分 | `rec.start(2000)` 是 2 秒分块 |
| 应用图标 | `build/icon.icns`（重新生成后打包） | 可用 `build/icon-1024.png` 换图 |

## 3. 数据都存哪（重要）

所有数据都在：`~/Library/Application Support/interview-simulator/`

```
├── settings.json            # 设置（API Key、参数、风格）
├── data/
│   ├── materials/           # 导入的资料（english/ / major/ / resume/）
│   ├── schools.json         # 学校风格库
│   ├── history/             # 面试记录 + 评分报告
│   ├── models/              # Whisper 语音模型（464MB，别删）
│   ├── venv-whisper/        # 识别引擎环境（别删）
│   └── logs/                # 识别日志（排查用）
```

**备份**：复制整个 `interview-simulator` 文件夹即可备份全部数据。
**恢复**：把备份文件夹放回原位置即可。

> 新版打包后数据目录被统一固定到这里，重装/升级不会丢数据。

## 4. 重新打包常见问题

| 现象 | 处理 |
|---|---|
| `build:mac` 卡在下载 | 走国内镜像，多等一会；若失败重试一次 |
| 打包后的 app 双击提示"无法验证开发者" | 右键点击 app → 打开；或 系统设置→隐私与安全性→仍要打开（首次一次即可，无签名 app 的正常现象） |
| 改了 main 进程代码没生效 | 必须重新 `npm run build:mac`（dev 的热更新只覆盖界面部分） |
| 找不到新页面 | 检查 `App.tsx` 是否注册了导航项 |

## 6. 实操篇：从"想改"到"用上新版"的完整流程

### 6.1 用什么工具打开和编辑代码

- **推荐**：VS Code（免费）——打开项目文件夹，左侧看到全部文件，按 `Cmd+F` 搜索、`Cmd+S` 保存。
- 不装软件也行：macOS 自带的「文本编辑」（TextEdit）可打开 `.ts`/`.tsx`/`.css` 文件，但功能弱。
- 只改配置类内容（见 6.3）时，甚至可以只改 `settings.json`，不用碰代码。

### 6.2 完整更新流程（5 步）

```text
① 关闭正在运行的应用
② 改代码（或配置）
③ 终端执行：npm run typecheck && npm run dev   ← 预览验证没问题
④ 终端执行：npm run build:mac                  ← 生成新 dmg（约 1-3 分钟）
⑤ 打开 dist/面试模拟器-新版本号-arm64.dmg 安装（覆盖旧版）
```

> 数据（资料/模型/历史）都在 `~/Library/Application Support/interview-simulator`，**重装不会丢**，无需备份也能升级；保险起见可先复制该文件夹。

### 6.3 三种修改难度

| 难度 | 做法 | 示例 |
|---|---|---|
| 🟢 免改代码 | 应用内设置直接改 | 题数、时长、音色、风格滑块、学校笔记 |
| 🟡 改配置/文字 | 用编辑器改 1 处，改完重新打包 | 改预设风格描述、改默认题数、改界面文字 |
| 🔴 改逻辑/功能 | 改代码（可能需要改多处） | 加新环节、改识别流程、改报告结构 |

### 6.4 版本号怎么更新

每次打包前建议把版本号 +1，方便区分新旧安装包：

```
package.json 第一行： "version": "0.1.0"  →  改成 "0.2.0"
```

改完后 `npm run build:mac` 生成的 dmg 文件名会自动带新版本号。

### 6.5 手把手示例

**示例 A：把「温和引导型」的描述改得更温和**
1. 打开 `src/main/interview.ts`
2. `Cmd+F` 搜索「温和引导型」
3. 找到 `PRESET_DESC` 里那行中文描述，改成你要的文字（如"语气非常亲切，多表扬，任何回答都先肯定再提建议…"）
4. 保存 → `npm run build:mac` → 安装新版

**示例 B：把默认英语题数从 5 改成 7**
1. 打开 `src/main/store.ts`
2. 搜索 `englishQuestions: 5`，改成 `englishQuestions: 7`
3. 保存 → 重新打包（或直接在应用「设置」页改，效果相同、更简单）

**示例 C：改界面标题"面试模拟器"为其他名字**
1. 打开 `src/renderer/src/App.tsx` 和 `src/renderer/index.html`
2. 搜索「面试模拟器」全局替换
3. 保存 → 重新打包（注意 `package.json` 的 `productName` 和 `electron-builder.yml` 也有一处，一起改）

### 6.6 常见"改了没效果"的坑

| 坑 | 原因 | 解法 |
|---|---|---|
| 界面改了没反应 | dev 模式窗口没刷新 | 关掉重开 `npm run dev`；或改的是 main 进程必须重新打包 |
| 打包后还是旧版 | 安装的是旧 dmg | 确认安装的是 `dist/` 里**最新生成**的 dmg（看时间戳/版本号） |
| 改完出现红字报错 | 代码写错了 | 先 `npm run typecheck`，按提示改；不行就把错误信息发我 |
| 不确定改哪 | — | 直接问我（把想实现的效果说清楚即可） |
